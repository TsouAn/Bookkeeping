# Spec Delta

## Purpose

管理個人收支記錄：讓使用者新增、檢視與刪除收入及支出，並確保每筆記錄的欄位都正確有效。

## ADDED Requirements

### Requirement: 新增收支記錄
系統 SHALL 允許使用者新增一筆收支記錄，欄位為：類型（`income` 或 `expense`）、金額、分類、日期、備註（選填）。新增成功後 MUST 回傳完整記錄（含系統產生的 `id`）。

#### Scenario: 新增支出成功
- **WHEN** 使用者送出 `POST /api/transactions`，內容為 類型 `expense`、金額 `120`、分類 `餐飲`、日期 `2026-10-20`、備註 `午餐`
- **THEN** 系統回傳 `201 Created`
- **AND** 回應內容包含新的 `id` 與送出的所有欄位

#### Scenario: 新增收入成功
- **WHEN** 使用者送出類型 `income`、金額 `50000`、分類 `薪資`、日期 `2026-10-05`
- **THEN** 系統回傳 `201 Created`
- **AND** 備註為空字串

#### Scenario: 新增後立即可在列表看到
- **WHEN** 新增一筆記錄成功
- **THEN** 下一次取得列表時該筆記錄出現在結果中

### Requirement: 金額驗證
金額 MUST 為大於 0 且不超過 10,000,000 的整數（新台幣元）。不合法時系統 MUST 拒絕並回傳 `400`，不得寫入資料。

#### Scenario: 金額為 0 或負數
- **WHEN** 使用者送出金額 `0` 或 `-50`
- **THEN** 系統回傳 `400`，錯誤訊息為「金額必須是大於 0 的整數」

#### Scenario: 金額含小數
- **WHEN** 使用者送出金額 `99.5`
- **THEN** 系統回傳 `400`，錯誤訊息為「金額必須是大於 0 的整數」

#### Scenario: 金額超過上限
- **WHEN** 使用者送出金額 `10000001`
- **THEN** 系統回傳 `400`，錯誤訊息為「金額不可超過 10,000,000」

### Requirement: 類型與分類驗證
類型 MUST 為 `income` 或 `expense`。分類 MUST 屬於該類型的預設分類清單：支出為「餐飲、交通、購物、娛樂、居家、醫療、其他」，收入為「薪資、獎金、投資、其他」。

#### Scenario: 類型不合法
- **WHEN** 使用者送出類型 `transfer`
- **THEN** 系統回傳 `400`，錯誤訊息為「類型必須是 income 或 expense」

#### Scenario: 分類與類型不符
- **WHEN** 使用者送出類型 `income`、分類 `餐飲`
- **THEN** 系統回傳 `400`，錯誤訊息為「分類不屬於此類型」

### Requirement: 日期與備註驗證
日期 MUST 為存在的日曆日期，格式 `YYYY-MM-DD`。備註為選填，長度 MUST 不超過 100 字。

#### Scenario: 日期格式錯誤或不存在
- **WHEN** 使用者送出日期 `2026/10/20` 或 `2026-02-30`
- **THEN** 系統回傳 `400`，錯誤訊息為「日期格式必須是 YYYY-MM-DD」

#### Scenario: 備註過長
- **WHEN** 使用者送出 101 字的備註
- **THEN** 系統回傳 `400`，錯誤訊息為「備註不可超過 100 字」

### Requirement: 收支列表
系統 SHALL 提供 `GET /api/transactions` 列出記錄，可用 `month=YYYY-MM` 篩選月份。排序 MUST 為日期新到舊；同日期時較晚新增者在前。

#### Scenario: 依日期新到舊排序
- **WHEN** 已有日期 `2026-10-01`、`2026-10-15`、`2026-10-08` 三筆記錄，使用者取得列表
- **THEN** 回傳順序為 `2026-10-15`、`2026-10-08`、`2026-10-01`

#### Scenario: 依月份篩選
- **WHEN** 使用者取得 `month=2026-10` 的列表
- **THEN** 只回傳日期在 2026 年 10 月的記錄

#### Scenario: 沒有任何記錄
- **WHEN** 資料庫沒有記錄時取得列表
- **THEN** 系統回傳 `200` 與空陣列

### Requirement: 刪除收支記錄
系統 SHALL 允許使用者以 `DELETE /api/transactions/:id` 刪除單筆記錄。前端在刪除前 MUST 請使用者確認。

#### Scenario: 刪除成功
- **WHEN** 使用者刪除存在的記錄
- **THEN** 系統回傳 `204 No Content`
- **AND** 該記錄不再出現在列表中

#### Scenario: 刪除不存在的記錄
- **WHEN** 使用者刪除不存在的 `id`
- **THEN** 系統回傳 `404`，錯誤訊息為「找不到此筆記錄」

#### Scenario: 使用者取消刪除
- **WHEN** 使用者在畫面上點「刪除」但在確認對話框選擇取消
- **THEN** 記錄保留，不送出刪除請求

### Requirement: 資料持久保存
記錄 MUST 存放在後端資料庫中，重新啟動伺服器或重新整理頁面後資料仍然存在。

#### Scenario: 重新啟動後資料仍在
- **WHEN** 新增記錄後重新啟動後端伺服器
- **THEN** 列表仍包含該筆記錄
